## 1. R2-01：补全返回原站时的跨源请求头清理

改动位置：[internal/runner/policy.go](../internal/runner/policy.go)，checkRedirectTarget。

同时保留两种判断：

```go
outsideInitial := !sameOrigin(first, req.URL)
crossesPrevious := !sameOrigin(previous, req.URL)

if outsideInitial || crossesPrevious {
    // 执行现有的跨源授权、正文重放授权和 Header 白名单清理。
}
```

这里是实现方向示意，实际代码继续保留 URL 合法性、HTTPS 降级、URLPolicy、Context 等检查。

outsideInitial 保证目标只要不属于最初站点，就持续受到现有约束；crossesPrevious 补上 B→A 的返回路径。两者合并后，A→B、B→B、B→A 都不会绕过清理，A→A 则保留当前同源行为。

不能只把 first 换成 previous：标准 Client 在后续跳转中可能重新复制初始自定义头，B→B 仍需防止初始认证信息被带回来。

处理顺序保持为：用户 CheckRedirect → 基础目标/跳转/请求头策略 → 空白幂等键清理 → 当前跳转的重试资格判断 → 实际发送。HTTPS 降级继续按相邻两跳判断。

CookieJar 仍按最初站点隔离。返回 A 时，清理手工 Header 与 CookieJar 按 A 的域规则重新取 Cookie 是两件事；不把 B 变成新的可信源。

### 行为变化

- AllowCrossOriginRedirect=false 时，跨源跳转继续被拒绝。
- 开启跨源后，返回最初站点的这一步也执行跨源白名单清理。
- 默认不在白名单中的 Referer、手工认证头等会被移除，包括返回原站时可能重新复制的初始头。
- 调用方显式将 Referer 列入白名单时，继续遵守该授权。
- 307/308 等跨源正文重放、跳转次数限制及丢失幂等保护后的禁止重试规则继续生效。

### 回归验收

| 场景 | 预期 |
| --- | --- |
| A→A | 同源跳转保持原行为 |
| A→B，未开启跨源 | 拒绝，B 不收到请求 |
| A→B→A | 返回 A 时无默认不允许的 Referer |
| A→B→B→A | B 的两跳不出现初始自定义凭证，A 不收到 B 的带令牌 Referer |
| A→B→C | 保持现有跨源清理 |
| 显式允许 Referer | 按白名单保留，验证配置仍有效 |
| 307/308 未授权跨源正文 | 拒绝并关闭重开的正文 |
| HTTPS 降级、CookieJar、幂等键清理 | 既有回归继续通过 |

至少为 A→B→B→A 保留真实本地 HTTP 服务测试，直接检查服务端收到的头。

## 2. R2-02：合并超时原因，保留不可重试错误

改动位置：[internal/runner/execute.go](../internal/runner/execute.go)、[internal/validator/safe.go](../internal/validator/safe.go)。

### 错误合并规则

| 原结果 | 观察到 Context 错误 | 最终错误 |
| --- | --- | --- |
| 成功 | 无 | nil |
| 失败 | 无 | 原错误 |
| 成功 | 有 | Context 错误，不能把迟到结果判为成功 |
| 失败 | 有 | 保留原错误并附加 Context 错误 |
| 错误链已包含同一个 Context 原因 | 有 | 复用原错误，避免重复叠加 |

增加一个只负责合并的内部工具，建议放在新的 internal/utils/context_error.go。该工具不依赖 tn、不判断业务重试策略，避免 tn 已依赖 utils 时产生循环依赖。

示意实现：

```go
func MergeContextError(err, ctxErr error) error {
    if ctxErr == nil {
        return err
    }
    if err == nil {
        return ctxErr
    }
    if errors.Is(err, ctxErr) {
        return err
    }
    return errors.Join(err, ctxErr)
}
```

使用 [errors.Join](https://pkg.go.dev/errors#Join) 保留多个原因后，调用方继续通过 errors.Is / errors.As 判断。例如 NoRetry 与单次超时同时发生时，ErrPermanent、原始业务错误和 DeadlineExceeded 均可查询到。错误文本可能同时包含多个原因，调用方的分类逻辑应使用错误链判断。

### 接入范围与重试顺序

1. 验证器先完成验证错误包装或 panic 转换，再合并 Context 原因，保留 ErrValidation、NoRetry 和原始业务原因。
2. Execute 的 Body 打开失败、perform 返回后的单次期限复核、总期限复核，以及尝试日志回调后的总期限复核，都按同样规则保留当前结果的原因。
3. 合并后先检查取消、永久错误、Writer 错误、地址/容量等禁止重试依据，再考虑普通可重试失败及 RetryDecider。任意禁止标记成立时，RetryDecider 不能放行。
4. 只有单次超时、没有禁止标记时，继续沿用当前允许重试的规则；仍须满足方法、次数、正文重放及总期限等条件。
5. 整次调用的 Context 已取消或总期限已到时结束调用，即使保留了其他错误也不再重试。
6. 重试等待阶段仍以等待取消/超时作为该阶段错误，不把历次失败累计到一棵越来越大的错误树。

期限检查必须在主动调用 attemptCancel 之前读取单次 Context 的错误。不能在清理 cancel 后再次读取该 Context 并据此重写业务结果，否则正常结束也会被误记为取消。总 Context 的主动清理同理。

有真实失败时保留其阶段，例如 PhaseResponseWrite 或 PhaseValidation；原本成功、只在结束复核发现超时时使用 PhaseAttempt。日志扩展执行期间才发生的取消，按最终汇总时能观察到的状态处理，不回改已经派发的事件。

### 回归验收

- Writer 未写出任何字节，在单次期限结束后返回固定错误：只尝试一次，ErrResponseWrite、原始原因和 DeadlineExceeded 同时保留。
- 验证器在期限结束后返回 NoRetry：只尝试一次，ErrPermanent、ErrValidation、原始原因和 DeadlineExceeded 同时保留。
- 上述两种情况即使 RetryDecider 总返回 true，也不能发起下一轮，且不应调用它来放行禁止项。
- 普通单次超时仍可在总期限内重试成功。
- 总期限和上游取消始终终止调用；源错误仍可诊断。
- 正常成功请求不会因为本函数主动 cancel 而变成失败。
- 已写出数据的 ApiTo 继续不重试。

使用 ctx.Done() 等待期限触发，避免依赖 sleep 与调度碰撞。重点验证实际调用次数、错误链和日志阶段。

实现目标是成功路径不创建合并错误，不增加共享锁或后台 goroutine。

## 3. R2-03：在 map 操作前验证中间件实际值

改动位置：[mdw/chain.go](../mdw/chain.go)，MiddlewareChain.Build。

将原型和 Clone 结果的检查统一为：

1. 检查 nil 与带类型 nil。
2. 用 reflect.ValueOf(mw).Comparable() 判断实际值能否安全比较。
3. 通过之后才能访问 seen、seenNodes，或执行接口相等比较。
4. 保留现有重复节点、独立 Clone、循环引用检查，验证结束后再绑定下游。

有 interface/any 字段的结构体，其动态内容也参与比较安全性判断，应依据[实际值的 Comparable](https://pkg.go.dev/reflect#Value.Comparable)进行校验。

不能比较的中间件值返回明确错误，提示采用指针；NewClient / NewClientUncached 继续将建链错误包装为 ErrClientConfig。这个修补通过提前校验解决 map 操作的 panic，不增加扩展回调的统一 panic 接管策略。

不会要求所有中间件一律改为指针。合法可比较值继续可用；指针中间件内部持有切片、map 等业务数据也正常，因为参与比较的是指针身份。MiddlewareFactory 返回的普通 RoundTripper 不作为这些 map 的 key，其现有构造能力保留。

### 回归验收

- 原型是值结构体，any 内保存切片或 map：返回错误，不 panic。
- 原型为合法指针，但 Clone 返回上述不可比较值：同样返回错误。
- 带类型 nil 原型或 Clone：继续返回错误。
- 指针中间件内部持有切片：正常建链并发送。
- 重复原型、Clone 别名、循环节点、独立客户端复用等现有回归继续通过。
- 原型或 Clone 未通过检查时，保持先校验整组中间件、后绑定下游的顺序。

## 4. R2-04：分开记录单轮状态与最终汇总状态

改动位置：[internal/runner/execute.go](../internal/runner/execute.go)、[logging/events.go](../logging/events.go)，并补充 tn.RetryInfo 的字段说明。

推荐沿用当前约定，但把范围说明清楚：

CallResult.StatusCode 表示本次调用中，执行层最近一次取得的最终响应状态。按每轮 Client.Do 返回的 Response 统计；没有取得过响应才为 0。不把重定向链的所有中间响应单独计入该字段。

增加两个当前调用内的局部变量：

| 变量 | 含义 | 使用位置 |
| --- | --- | --- |
| attemptStatusCode | 当前轮的响应状态，无响应为 0 | RetryInfo、RetryEvent 及当前轮的决策 |
| lastResponseStatusCode | 最近一轮实际返回过响应的状态，未收到过为 0 | CallResult |

每次 perform 返回后，仅当 attemptStatusCode>0 时更新 lastResponseStatusCode。最终 OnEnd 使用后者。Body 打开失败或本轮网络错误无响应时，不清空已有汇总状态。

不能只让现有 status 一直保留非零值：它还会传给重试回调，那样第二轮没有响应的网络错误就可能被错误描述为第二轮收到了 503。

### 行为与验收

| 尝试顺序 | 最后一轮状态 | CallResult.StatusCode |
| --- | ---: | ---: |
| 503 → 网络错误且无响应 | 0 | 503 |
| 503 → 200 | 200 | 200 |
| 网络错误 → 网络错误 | 0 | 0 |
| 503 → Body 打开失败 | 无响应 | 503 |

如果 Client.Do 返回错误且同时带有 Response，也要更新其真实状态码。单轮是否拿到响应仍看 AttemptResult.Response；整次调用成功与否仍看 Err。最终失败时汇总状态可以非零。

不新增公开字段。新增的状态仅是每次调用自己的整数变量，不共享、不加锁。

## 7. 实施结果（2026-11-16）

四项均已完成，公开调用方式及配置字段保持不变。

1. checkRedirectTarget 同时比较初始地址与上一跳，真实 HTTP 回归确认返回原站时清理未授权 Referer 和初始自定义凭证；同源跳转、显式 Referer 白名单继续可用。
2. 新增 [MergeContextError](../internal/utils/context_error.go)，用于执行层和验证器的期限复核；同时接入 ReadBounded、CopyBounded 及请求重放缓存的容量错误映射，避免原因在底层提前丢失。EOF 正常结束不被当作额外读取失败。Writer、NoRetry、地址拒绝及容量超限遇到超时后仍禁止重试，普通单次超时仍可重试成功。
3. 原型与 Clone 结果都在 map 操作前检查实际值；切片/map 动态内容导致的构造 panic 已转换为配置错误。合法可比较值、指针内部的切片及原有独立建链行为继续通过回归。
4. 单轮状态与最近响应状态使用独立局部变量。503 后无响应时最终汇总保留 503；当前轮的 RetryInfo、RetryEvent 仍为 0；Body 打开失败、成功重试和带响应的跳转错误均有回归覆盖。
