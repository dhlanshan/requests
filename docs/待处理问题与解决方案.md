## C1：地址规则的落地方式

相关代码：[network_policy.go](../internal/core/network_policy.go)。

规则来源使用 [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry/) 和 [IANA IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry/)。特殊用途记录是否适合作为公网目的地址，需要结合目的地址与全球可达属性；不能只把 IsGlobalUnicast 当成公网证明。

推荐把注册表数据快照或生成依据纳入仓库，生成带来源和日期的静态规则文件。更具体前缀优先于大网段，避免漏掉排除项，也避免粗粒度规则遮住明确的例外。对特殊类别中的未知属性采取保守策略。

普通请求读取只读规则。更新数据时通过代码审查及回归发布，不在请求路径中动态拉取远程规则。AllowedHosts 继续是域名授权，不替代实际 IP 安全检查。

## C2：先统一长度语义，再规范化空正文

相关代码：[request.go](../internal/runner/request.go)、[http_body.go](../internal/lz/http_body.go)。

这是修补中必须保留的区别：

- BodyFactory / BodySource 按协议返回 0，表示它声明正文准确为空。
- 普通 Reader 没有声明长度时，net/http 的 ContentLength=0 可能表示未知长度。准备 bodyPlan 时应将这种情况表示为 -1，不能按空正文探测、拒绝或丢弃。
- 显式 Content-Length: 0 仍需要确认正文为空；已有探测逻辑可归并复用。
- http.NoBody 自身已知为空，可以直接走零长度路径；若同时声明正长度，应在发送前拒绝不一致配置。

在首次打开与 GetBody 重开时共用空正文处理：最多读取一个字节，受当前 Context 控制；确认 EOF 后关闭原流并返回 http.NoBody。读到数据或发生错误时保留错误并关闭流，不把非空内容悄悄抹掉。

pf 只在正文完整恢复且数据长度为 0 时设置 NoBody 和对应 GetBody；部分读取、截断、读取失败仍保留原有恢复与错误语义。原本没有 chunked 的空请求不能因工具读取而变成 chunked；原来显式存在的传输编码不在本修补中随意重写。

## C3：保留 panic 传播，修正异常汇总

相关代码：[execute.go](../internal/runner/execute.go)、[stream.go](../internal/runner/stream.go)、[events.go](../logging/events.go)、[errors.go](../tn/errors.go)。

推荐保留当前对非日志业务扩展的 panic 传播行为。修补目标是异常状态与已接管资源的生命周期。

实现采用独立执行主体和外层结束观察器。主体正常返回后才标记“正常结束”；外层 defer 用该标记区分正常返回、panic 或其他异常退出。异常时用新增的 PhaseAborted 和固定 ErrExecutionAborted 标记汇总，不把原始 panic 文本拼进日志。若此前已有当前失败原因，则与异常标记合并保留。

实现不调用 recover，不持有或改写 panic 值：通过 defer 完成清理和结束记录，由 Go 继续传播原异常，因此保留调用方原来的 recover 行为。正常业务返回错误继续使用原阶段与错误，不当作 panic。

每次尝试在打开请求流后立即建立清理兜底，保证已接管 Body、attemptCancel 和 Limiter 名额都能释放。保留已有“先清理、后结束日志”的顺序。单次期限复核仍在主动 attemptCancel 之前完成，避免误判取消。

对于已经开始的尝试，补齐异常 OnAttemptEnd；整次调用 OnEnd 最多一次。工厂内部尚未成功返回给请求执行层的资源，仍由工厂自身负责清理。若识别到 Goexit 等没有正常返回的退出，也不能标成 complete。

## C4：把 Context 复核补到回调后与准备失败出口

相关代码：[execute.go](../internal/runner/execute.go)、[request.go](../internal/runner/request.go)、[context_error.go](../internal/utils/context_error.go)。

建立总 Context 后，检查初始 URLPolicy 返回、公共 Body 准备失败以及 RetryDecider 返回等关键出口。每次先完成当前错误包装，再复核总 Context，复用 MergeContextError 保留两个原因。

RetryDecider 的方向示意：

```go
retry = p.RetryDecider(ctx, info)
if ctxErr := ctx.Err(); ctxErr != nil {
    return body, header, utils.MergeContextError(err, ctxErr)
}
if !retry {
    return body, header, err
}
```

URLPolicy 的错误继续保留 ErrTargetBlocked 和 RequestError 的安全展示能力；读取、打开流等原因也继续可查询。回调返回 nil 但期限已经结束时，同样停止后续工作。

错误仅合并当前操作与当前 Context 原因。重试等待阶段独立表示等待失败，不积累整个调用中每一轮的错误树。

## C5：明确可识别的证书验证错误

相关代码：[retry.go](../internal/runner/retry.go)。

推荐将证书分类拆成单独内部判断，覆盖已发现的标准类型及其包装：三类现有 x509 错误的值与指针、SystemRootsError 的值与指针、*tls.CertificateVerificationError。按标准证书验证错误类型维护回归集合；未知的应用自定义验证错误使用现有 NoRetry 明确表达永久失败。

用 errors.As 沿包装链判断，不用错误文本匹配证书类别。禁止判断始终先于 RetryDecider。TLS 握手时普通网络中断继续按网络错误分类，不能因属于 TLS 场景就全部归为证书失败。

验收矩阵至少包括：直接值、直接指针、fmt 包装、errors.Join、TLS 包装，以及 RetryDecider 总返回 true 的对照。这里修正的是无效重试策略，不是放宽证书验证。

## D1：建议的受控 TLS 配置范围

相关代码：[ClientParam](../tn/client.go)、[客户端构造](../internal/core/client.go)、[网络策略](../internal/core/network_policy.go)。

推荐先增加窄范围 TLSOptions，而非直接开放任意拨号行为。首批字段覆盖 RootCAs、客户端 Certificates、MinVersion / MaxVersion；零值沿用标准库策略。不提供绕过证书校验、改写目标或重设拨号器的选项。

构造时复制证书池及证书配置切片；证书和私钥实现按只读使用约定共享。由库构造 TLS 配置与 Transport，再叠加现有网络策略，不能因配置了 CA 或客户端证书而绕过 DNS/IP 校验。未启用网络策略的现有自定义 Transport 能力保留。

证书池和私钥等配置不能用简单指针相等可靠证明语义相同。命名构造可沿用不透明配置的保守策略：配置型实例通过 GetClient 明确复用，变化时显式 Reset；动态证书场景先采用独立客户端，后续再设计专门更新能力。增加字段时同步更新 Client 签名与配置隔离测试。

## D2：建议的客户端命名行为

相关代码：[client.go](../client.go)、[internal/core/client.go](../internal/core/client.go)、[client_store.go](../internal/core/client_store.go)。

推荐行为：

- NewClient 的 SpaceName 为空：创建独立客户端，不进入命名 LRU。
- SpaceName 非空：保留命名复用、配置冲突和 Reset 替换规则。
- GetClient 空名称：返回未找到；GetClient("master") 查询显式命名的 master。
- NewClient 的 Reset=true 要求显式名称，避免调用者误以为重置了某个共享默认实例。
- NewClientUncached 继续是明确的独立构造入口；其 SpaceName / Reset 不参与行为。
- Api(nil,p) 继续使用其共享默认客户端；该入口与命名缓存分别说明。

这是公开行为设计调整，不是实现已违反现有文档。应作为单独变更审阅，更新示例和默认行为测试。
